# 0.1.0b3 acceptance — 14 October 2026

Base: main `76b8cd6f26be67fc35c9b0515a54f6bee9214f8c`.

Decision: retain an exact, tested core dependency but advance it from
`notanda==1.3.1` to `notanda==1.3.2`. Publish as `notanda-mcp==0.1.0b3`
(Registry version `0.1.0-beta.3`). The server behavior and MCP SDK pin
(`mcp==1.30.0`) are unchanged. A future core version requires a new compatibility
check and MCP release; it must not be implicitly advertised as supported.

## Installation regression and deterministic checks

On Windows with CPython 3.12.14, a fresh virtual environment was populated with
the published PyPI `notanda==1.3.2`. A pip dry run for published MCP Beta 2
selected `notanda==1.3.1`, reproducing the reported dependency downgrade without
changing that environment. Installing the built Beta 3 wheel instead preserved
`notanda==1.3.2`. `pip check` passed and all **23 MCP tests passed** against the
installed wheel and released core, including actual stdio server processes.
The wheel and source distribution passed `twine check --strict`.

The publication workflow now installs core 1.3.2 before the MCP wheel and asserts
that the installed core remains 1.3.2. This exercises the reported installation
order on Python 3.12 in CI as well.

## Installation guidance

A dedicated environment remains recommended. For Beta 3 with core 1.3.2,
isolation is no longer required to prevent the reported downgrade. Beta 2 or a
different core version must use a separate environment. Documentation states
the exact dependency and the limitation for future core versions explicitly.

External unassisted developer acceptance remains pending. These technical tests
do not close that separate usability criterion. Publication completion is
recorded by the release workflow and public registries, not asserted by this file.
